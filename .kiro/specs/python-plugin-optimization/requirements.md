# Python 插件优化与扩展 - 需求文档

## 1. 项目概述

### 1.1 背景
智能审计系统（tjsj）是一个基于 Django 5.0 的 Web 应用，当前已实现用户认证、网站设置管理、图片上传、水印处理等核心功能。随着业务发展，需要对现有技术栈进行优化和扩展，以提升系统性能、安全性和可维护性。

### 1.2 当前技术栈
- **Web 框架**: Django 5.0, Django REST Framework 3.14
- **数据库**: MySQL (mysqlclient 2.2+)
- **跨域支持**: django-cors-headers 4.3+
- **API 文档**: drf-yasg 1.21+
- **对象存储**: minio 7.2+
- **图像处理**: Pillow 10.0+
- **配置管理**: python-dotenv 1.0+

### 1.3 业务价值
- 提升系统响应速度和并发处理能力
- 增强 API 安全防护，防止恶意攻击
- 建立完善的监控和日志体系，快速定位问题
- 提升开发效率和代码质量
- 降低运维成本和故障率

## 2. 功能需求

### 2.1 缓存与性能优化

#### 需求描述
当前系统使用 Django 内置的内存缓存，存在以下问题：
- 缓存数据无法在多个进程间共享
- 服务重启后缓存数据丢失
- 无法支持分布式部署

#### 业务目标
- 将验证码、登录失败记录等热点数据缓存到 Redis
- 缓存网站设置、用户信息等频繁查询的数据
- 支持分布式缓存，提升系统扩展性
- 减少数据库查询次数，提升响应速度 30% 以上

#### 验收标准
- [ ] 成功集成 django-redis 和 redis 客户端
- [ ] 验证码和登录锁定功能迁移到 Redis
- [ ] 网站设置查询接口响应时间降低 50%
- [ ] 支持多实例部署，缓存数据共享
- [ ] 提供缓存监控和统计功能

### 2.2 异步任务队列

#### 需求描述
当前系统的图片处理、文件上传等操作都是同步执行，导致：
- 用户上传大图片时接口响应慢
- 定期清理任务需要手动执行
- 无法处理复杂的后台任务

#### 业务目标
- 异步处理图片上传和透明化处理
- 定期清理过期验证码和未使用的 MinIO 对象
- 支持任务重试和失败告警
- 提供任务监控和管理界面

#### 验收标准
- [ ] 成功集成 Celery 和 Redis 作为消息队列
- [ ] 图片上传接口立即返回，后台异步处理
- [ ] 实现定时任务：每小时清理过期验证码
- [ ] 实现定时任务：每天清理未使用的 MinIO 对象
- [ ] 提供 Celery 任务监控界面（Flower）
- [ ] 任务失败自动重试 3 次

### 2.3 API 限流与安全增强

#### 需求描述
当前系统虽然有登录锁定机制，但缺少全局的 API 限流保护：
- 验证码接口可能被恶意刷取
- 注册接口可能被批量注册
- 缺少 IP 黑名单管理

#### 业务目标
- 对公开接口实施频率限制
- 防止暴力破解和 DDoS 攻击
- 支持 IP 黑白名单管理
- 记录异常访问行为

#### 验收标准
- [ ] 成功集成 django-ratelimit
- [ ] 验证码接口限制：每 IP 每分钟最多 10 次
- [ ] 注册接口限制：每 IP 每小时最多 5 次
- [ ] 登录接口限制：每 IP 每分钟最多 20 次
- [ ] 超过限制返回 429 状态码和友好提示
- [ ] 提供管理后台查看限流统计

### 2.4 数据验证增强

#### 需求描述
当前系统使用手动验证，代码冗长且容易出错：
- 参数验证逻辑分散在各个视图函数中
- 缺少统一的错误处理机制
- 复杂查询过滤功能不足

#### 业务目标
- 统一的数据验证和序列化机制
- 更强大的查询过滤能力
- 减少重复代码，提升可维护性

#### 验收标准
- [ ] 成功集成 marshmallow 或 django-filter
- [ ] 重构网站设置相关接口的验证逻辑
- [ ] 提供统一的错误响应格式
- [ ] 支持复杂的查询过滤（范围、模糊匹配等）
- [ ] 验证逻辑代码量减少 40%

### 2.5 监控与日志系统

#### 需求描述
当前系统缺少生产环境的监控和日志聚合：
- 错误信息只记录在本地日志文件
- 无法实时追踪线上问题
- 缺少性能指标监控

#### 业务目标
- 实时错误追踪和告警
- 性能指标监控和可视化
- 结构化日志记录
- 快速定位和解决线上问题

#### 验收标准
- [ ] 成功集成 Sentry 进行错误追踪
- [ ] 所有未捕获异常自动上报到 Sentry
- [ ] 集成 Prometheus 导出性能指标
- [ ] 使用 structlog 实现结构化日志
- [ ] 关键操作（登录、上传）记录详细日志
- [ ] 提供 Grafana 监控面板

### 2.6 文件处理增强

#### 需求描述
当前系统依赖文件扩展名判断类型，不够准确：
- 可能被恶意文件绕过
- 不支持某些新格式（HEIF/HEIC）
- 缺少图片压缩优化

#### 业务目标
- 更准确的文件类型检测
- 支持更多图片格式
- 自动压缩优化图片大小

#### 验收标准
- [ ] 成功集成 python-magic 进行文件类型检测
- [ ] 集成 pillow-heif 支持 HEIF/HEIC 格式
- [ ] 上传图片自动压缩到合理大小
- [ ] 阻止非图片文件上传
- [ ] 支持 WebP 格式转换

### 2.7 测试工具体系

#### 需求描述
当前项目缺少自动化测试：
- 没有单元测试和集成测试
- 代码变更容易引入 bug
- 缺少测试覆盖率统计

#### 业务目标
- 建立完整的测试体系
- 提升代码质量和可靠性
- 支持持续集成（CI）

#### 验收标准
- [ ] 成功集成 pytest 和 pytest-django
- [ ] 为核心功能编写单元测试（认证、上传、设置）
- [ ] 测试覆盖率达到 70% 以上
- [ ] 集成 factory-boy 生成测试数据
- [ ] 配置 CI 自动运行测试

### 2.8 开发工具优化

#### 需求描述
当前开发调试效率较低：
- 缺少可视化的调试工具
- 数据库查询性能难以分析
- 缺少便捷的管理命令

#### 业务目标
- 提升开发调试效率
- 快速定位性能瓶颈

#### 验收标准
- [ ] 成功集成 django-debug-toolbar

- [ ] 集成 django-extensions 增强管理命令
- [ ] 使用 IPython 作为交互式 shell
- [ ] 提供便捷的数据导入导出命令

## 3. 非功能需求

### 3.1 性能要求
- API 响应时间 P95 < 200ms
- 支持 1000+ 并发用户
- 数据库查询优化，避免 N+1 问题
- 静态资源 CDN 加速

### 3.2 安全要求
- 所有敏感配置使用环境变量
- API 密钥和密码加密存储
- 定期更新依赖包，修复安全漏洞
- 生产环境关闭 DEBUG 模式

### 3.3 可维护性要求
- 代码符合 PEP 8 规范
- 关键函数添加文档字符串
- 配置文件清晰易懂
- 提供详细的部署文档

### 3.4 兼容性要求
- 兼容 Python 3.11+
- 兼容 Django 5.0+
- 向后兼容现有 API 接口
- 支持 Docker 容器化部署

- django-redis（缓存优化）

**预期收益**:
- 响应速度提升 30%

- 减少 bug 引入

### 4.2 第二阶段（中优先级）
**目标**: 增强功能和安全性
- celery（异步任务）

**预期收益**:

- 系统安全性增强

### 4.3 第三阶段（低优先级）
**目标**: 优化开发体验
- django-debug-toolbar（调试工具）

## 5. 风险与约束

### 5.1 技术风险
- Redis 引入增加部署复杂度
- Celery 需要额外的消息队列服务
- 插件版本兼容性问题

### 5.2 业务风险
- 缓存策略不当可能导致数据不一致
- 异步任务失败可能影响业务流程
- 限流策略过严可能影响正常用户

### 5.3 约束条件
- 必须保持现有 API 接口兼容性
- 不能影响现有功能的正常使用
- 需要提供回滚方案
- 需要充分测试后再上线
