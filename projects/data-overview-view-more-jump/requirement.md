# 需求文档

## 1. 背景
- 业务背景：数据概览页的“任务状况排名”支持按分类查看（完成/运行/剩余/异常），但“查看更多数据”按钮当前没有跳转行为。
- 当前现状：用户从排名模块无法快速进入“数据调度”页面并延续当前关注的执行状态。
- 相关页面/模块：
  - `frontend/src/pages/(base)/data-fetch/data-overview/modules/TaskRanking.tsx`
  - `frontend/src/pages/(base)/data-fetch/data-schedule/index.tsx`

## 2. 目标
- 核心目标：为 `page.dataOverview.viewMoreData` 按钮增加跳转到 `/data-fetch/data-schedule` 的行为，并将当前执行状态一并带入目标页筛选。
- 预期价值：减少跨页面重复筛选操作，提升定位目标任务效率。

## 3. 范围
### 本次范围
- 增加 “查看更多数据” 按钮点击跳转。
- 定义排名分类到数据调度执行状态的映射并透传。
- 数据调度页读取 URL 状态并自动应用到筛选条件。

### 不在本次范围
- 不改后端接口。
- 不改数据调度页表格字段与视觉样式。

## 4. 用户故事
- 作为 `数据概览页面用户`，我希望 `点击查看更多数据后进入数据调度并自动带上当前执行状态筛选`，从而 `快速查看同类任务明细`。

## 5. 功能需求
- [ ] 需求 1：`page.dataOverview.viewMoreData` 按钮可点击跳转到 `/data-fetch/data-schedule`。
- [ ] 需求 2：跳转时透传执行状态筛选参数。
- [ ] 需求 3：数据调度页首次进入时自动应用该状态筛选并触发查询。
- [ ] 需求 4：保持原有 add/detail 模式行为不受影响。

## 6. 非功能需求
- 性能：不增加额外阻塞性请求。
- 兼容性：延续现有路由与查询参数机制。
- 可维护性：映射关系集中在排名模块，避免散落逻辑。

## 7. 数据与接口影响
- 前端影响：`TaskRanking.tsx` 与 `data-schedule/index.tsx`。
- 后端影响：无。
- 数据库影响：无。
- 第三方/MCP 影响：无。

## 8. 交互与界面说明
- 按钮文案与位置保持不变。
- 跳转后在数据调度页直接体现状态筛选。

## 9. 验收标准
- [ ] 在“完成/运行/剩余/异常”任一标签下点击“查看更多数据”，可进入 `/data-fetch/data-schedule`。
- [ ] 进入后 `taskStatus` 已按映射自动带入筛选。
- [ ] add/detail 模式页面不受该逻辑干扰。

## 10. 风险与疑问
- 风险：排名分类与数据调度状态枚举语义并非一一等价，需要明确映射约束。
- 疑问：`abnormal` 是否仅映射 `failed`（本次先按 `failed` 实现）。

## 11. 确认关卡
- 用户已明确要求实现跳转与状态透传，可进入编码阶段。
