# 需求文档

## 1. 背景
- 业务背景：数据调度页面当前列表接口未接入真实后端，页面搜索条件虽完整，但无法基于真实任务数据进行筛选。
- 当前现状：
  - 任务列表使用 `modules/mock.ts` 占位，真实数据源未接入；
  - 数据概览的项目状态统计已基于数据库（`c_r_cm_project` / `c_r_cm_file_prepare` / `c_r_cm_task_item_queue`）实现；
  - 数据调度列表与任务状况在业务上存在较高重合。
- 相关页面/模块：
  - `frontend/src/pages/(base)/data-fetch/data-schedule/index.tsx`
  - `frontend/src/pages/(base)/data-fetch/data-schedule/modules/ScheduleSearch.tsx`
  - `backend/api/views.py`
  - `backend/api/urls.py`

## 2. 目标
- 核心目标：设计数据调度列表查询接口，支持当前界面所有搜索条件，并尽量复用任务状况统计同一批库表。
- 预期价值：
  - 统一数据来源口径，减少概览与列表数据割裂；
  - 让数据调度页面具备可联调、可落地的真实查询能力；
  - 为后续列表、详情、日志接口形成一致契约。

## 3. 范围
### 本次范围
- 设计数据调度任务列表接口（只读）。
- 定义与当前界面一致的搜索参数。
- 定义返回字段、状态映射、分页与排序规则。
- 设计数据库查询方案（优先同任务状况统计使用同一套核心表）。
- 增加展示门禁规则：项目除 `industry` 非空外，必须同时存在 `c_r_cm_file_prepare` 与 `c_r_cm_task_item_queue` 关联数据。

### 不在本次范围
- 本次不实现后端代码。
- 本次不改前端页面交互与样式。
- 本次不新增数据库表结构。

## 4. 用户故事
- 作为 `数据调度页面用户`，我希望 `按项目名称、执行状态、匹配度区间、创建人、创建时间筛选任务列表`，从而 `快速定位任务并查看提取结果`。

## 5. 功能需求
- [ ] 需求 1：提供任务列表分页接口，返回页面所需字段。
- [ ] 需求 2：支持按项目名称模糊搜索。
- [ ] 需求 3：支持按执行状态多选搜索。
- [ ] 需求 4：支持按匹配度区间搜索。
- [ ] 需求 5：支持按创建人多选搜索。
- [ ] 需求 6：支持按创建时间区间搜索。
- [ ] 需求 7：支持 `current/size` 分页参数。
- [ ] 需求 8：仅展示满足以下全部条件的项目：
  - `c_r_cm_project.industry` 非空；
  - 存在 `c_r_cm_file_prepare.project_id = c_r_cm_project.project_id` 记录；
  - 存在 `c_r_cm_task_item_queue.project_id = c_r_cm_project.project_id` 且项目级队列（`file_id LIKE 'PROJECT:%'`）记录。

## 6. 非功能需求
- 性能：默认分页查询，避免全量返回。
- 安全性：仅认证用户可访问。
- 兼容性：入参与当前前端搜索表单语义一致。
- 可维护性：状态映射与筛选解析逻辑可复用到其他接口。

## 7. 数据与接口影响
- 前端影响：后续仅需将 `fetchScheduleList` 从 mock 切换到真实 API。
- 后端影响：新增列表查询接口与配套查询函数。
- 数据库影响：只读查询，优先复用 `c_r_cm_project`、`c_r_cm_file_prepare`、`c_r_cm_task_item_queue`。
- 第三方/MCP 影响：无。

## 8. 交互与界面说明
- 搜索条件保持现状：
  - 项目名称
  - 执行状态（多选）
  - 匹配度区间（min/max）
  - 创建人（多选）
  - 创建时间（区间）
- 表格字段保持现状：任务标识、项目名称、执行状态、执行进度、创建人、创建时间、完成时间。

## 9. 验收标准
- [ ] 接口参数覆盖当前界面全部搜索条件。
- [ ] 接口返回字段可直接驱动当前列表渲染。
- [ ] 查询口径与任务状况核心数据来源一致（同核心表）。
- [ ] 无 `file_prepare` 数据或无队列数据的项目不出现在列表中。
- [ ] 参数异常时有明确错误码与提示。

## 10. 风险与疑问
- 风险：`创建人/创建时间` 字段在不同表中可能命名不一致，需要实现前确认真实列名。
- 风险：`匹配度` 业务口径需要明确（本设计先按“执行进度百分比”处理）。
- 风险：不同环境数据完整性不一致，若仅按项目表起查会混入“无文件/无队列”的脏展示数据。
- 疑问：`abnormal` 在数据调度中的状态映射是否需要覆盖 `paused/stopped`。
