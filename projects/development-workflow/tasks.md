# 任务文档

## 1. 准备阶段
- [x] 完成 `requirement.md`
- [x] 完成 `design.md`
- [x] 编码前获得用户确认（本次仅文档沉淀，不涉及业务代码）

## 2. 前端任务
- [ ] 在前端项目中明确开发环境变量文件（例如 `.env.development`）并统一 API 基地址命名。
- [ ] 约定接口变更时同步更新 `frontend/src/service/types/` 与 `frontend-backend-contracts.md`。
- [ ] 形成前端联调自检清单（登录态、鉴权失败、空态、异常态）。
- [ ] 补充或更新前端文档（如新增模块说明）。

## 3. 后端任务
- [ ] 固化后端启动顺序：创建 venv -> 安装依赖 -> `migrate` -> `init_auth_data` -> `runserver`。
- [ ] 统一后端运行环境变量（`DB_HOST`、`DB_PORT`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`）。
- [ ] 新增模型字段时严格走 migration 流程，并同步更新后端知识库。
- [ ] 补充面向前端开发者的后端说明文档。

## 4. 联调任务
- [ ] 统一数据库方案（建议 Docker MySQL）并固定连接信息。
- [ ] DataGrip 建立开发库连接并验证基础表可查询。
- [ ] 对齐前后端请求与响应契约，重点验证登录和系统设置相关接口。
- [ ] 确认权限/鉴权影响（Token 刷新、失效、登出）。
- [ ] 确认数据库/配置项影响（端口、账号权限、字符集）。

## 5. 验证
- [ ] 执行相关检查/测试（至少覆盖一条完整业务链路）。
- [ ] 完成手工验证（前端页面操作 -> 后端日志 -> DataGrip 数据落库）。
- [ ] 记录已知限制（例如本机无 MySQL 服务时必须先启动容器）。

## 6. 交付
- [x] 总结变更文件及其用途
- [ ] 总结验证结果（待按文档执行一次完整演练后补全）
- [ ] 等待下一步指令

## 7. 后续默认执行顺序（执行手册）
- [ ] 需求阶段：在 `projects/<feature-name>/` 新建三件套文档。
- [ ] 设计阶段：确认接口、数据、迁移和回滚方案。
- [ ] 开发阶段：前后端并行，数据库变更先 migration。
- [ ] 联调阶段：先后端接口自测，再前端联调，再 DataGrip 校验。
- [ ] 交付阶段：更新契约文档和知识库，沉淀问题与解决方案。
