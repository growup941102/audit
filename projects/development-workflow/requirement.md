# 需求文档

## 1. 背景
- 业务背景：当前项目进入持续迭代阶段，需要稳定、可复制的研发协作流程，支撑前后端与数据库并行开发。
- 当前现状：前端（VS Code）、后端（PyCharm）、数据库（DataGrip）工具链已确定，但环境初始化、联调顺序、问题定位方式尚未统一。
- 相关页面/模块：
  - 前端：`frontend/`
  - 后端：`backend/`
  - 数据库：MySQL（后端配置见 `backend/tjsj/settings.py`）

## 2. 目标
- 核心目标：形成一套可直接执行的项目开发流程，降低环境问题和联调成本。
- 预期价值：
  - 新需求可按统一节奏推进（需求 -> 设计 -> 任务 -> 开发 -> 验证）。
  - 前后端数据库联调路径清晰，减少“连不上/字段不一致/回归遗漏”。
  - 问题发生时可快速定位责任层（前端、后端、数据库或环境）。

## 3. 范围
### 本次范围
- 工具协作规范：VS Code + PyCharm + DataGrip + Codex。
- 开发环境规范：Python venv、Node、MySQL（优先 Docker）。
- 数据库初始化规范：建库、迁移、种子数据初始化、DataGrip 连接。
- 联调与验证规范：接口契约对齐、回归检查清单、交付总结模板。
- 文档沉淀位置与更新规则。

### 不在本次范围
- 生产环境部署方案与运维自动化。
- 新业务功能与库表新增设计实现。
- CI/CD 平台改造。

## 4. 用户故事
- 作为 `项目开发者`，我希望 `拥有一套统一且可复现的开发流程`，从而 `在多工具协作中快速开发并稳定联调`。

## 5. 功能需求
- [ ] 需求 1：明确工具职责边界（前端、后端、数据库、协作中枢）。
- [ ] 需求 2：给出从零启动到可联调的标准步骤（含命令和校验点）。
- [ ] 需求 3：给出数据库创建与连接的统一方案（推荐与备选）。
- [ ] 需求 4：给出每次需求迭代的固定执行顺序和文档更新规则。
- [ ] 需求 5：给出常见故障快速排查路径（端口、连接、权限、契约）。

## 6. 非功能需求
- 性能：流程文档应在 5 分钟内可读完关键步骤。
- 安全性：开发默认使用最小权限账号，不在文档中硬编码生产密码。
- 兼容性：兼容 macOS 开发环境，命令优先选择项目当前可用工具。
- 可维护性：规范文档放在 `projects/` 并可持续迭代。

## 7. 数据与接口影响
- 前端影响：明确 API 基地址管理、联调顺序、回归点。
- 后端影响：明确迁移执行、初始化命令和配置约束。
- 数据库影响：统一 MySQL 开发库创建与连接方式。
- 第三方/MCP 影响：不强制依赖 MCP；数据库排查可选 MySQL MCP（只读优先）。

## 8. 交互与界面说明
- 可抽离的组件机会：不涉及 UI 组件改造。
- 需要覆盖的状态：加载中 / 空态 / 异常 / 成功（作为联调验收场景）。

## 9. 验收标准
- [ ] 文档中包含“环境初始化”完整步骤（含数据库启动与迁移）。
- [ ] 文档中包含“日常开发”标准节奏（需求、设计、任务、开发、验证、交付）。
- [ ] 文档中包含“故障排查”最小闭环（症状 -> 检查 -> 修复）。
- [ ] 团队成员可按文档独立完成一次从启动到联调的完整流程。

## 10. 风险与疑问
- 风险：本地数据库服务未启动或端口冲突导致 DataGrip/PyCharm 无法连接。
- 风险：前后端接口字段变更未同步导致联调失败。
- 疑问：后续是否统一采用 Docker 作为唯一数据库方案（建议是）。

## 11. 确认关卡
- 本次仅沉淀流程文档，不涉及业务代码变更。
