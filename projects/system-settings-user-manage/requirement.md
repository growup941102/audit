# 需求文档

## 1. 背景
- 业务背景：系统设置下需要独立的用户管理能力。
- 当前现状：现有 `manage/user` 页面字段与 `auth_user` 不匹配，后端无对应 CRUD 接口。
- 相关页面/模块：系统设置菜单、`auth_user` 表。

## 2. 目标
- 核心目标：新增“系统设置-用户管理”页面，完成 `auth_user` 的增删改查。
- 预期价值：统一用户维护入口，支持状态控制与密码更新。

## 3. 范围
### 本次范围
- 新增后端用户管理接口（列表/新增/编辑/删除）
- 新增前端页面（系统设置子菜单）
- 新增前端弹窗表单（用户名、密码、确认密码、邮箱、是否可用）
- 列表展示（用户名、状态、邮箱、创建时间、更新时间、操作）
- 明确密码加密机制（Django 哈希）

### 不在本次范围
- 角色权限分配
- 用户详情页扩展
- 非 `auth_user` 表结构扩展

## 4. 用户故事
- 作为 `系统管理员`，我希望在系统设置里维护用户信息并控制启停状态，从而快速完成账号治理。

## 5. 功能需求
- [x] 新增用户管理页面，挂在系统设置下
- [x] 提供用户列表查询
- [x] 提供新增用户能力
- [x] 提供编辑用户能力
- [x] 提供删除用户能力

## 6. 非功能需求
- 性能：列表分页查询，默认每页 10 条。
- 安全性：密码不明文入库，沿用 Django 哈希方案。
- 兼容性：保持现有接口返回结构 `code/data/msg`。
- 可维护性：前端拆分 Search/Modal/Index 三层。

## 7. 数据与接口影响
- 前端影响：新增系统设置子路由与页面组件。
- 后端影响：新增 `system-manage/users` 相关 API。
- 数据库影响：仅读写 `auth_user` 业务数据，无 DDL。
- 第三方/MCP 影响：无。

## 8. 交互与界面说明
- 可抽离的组件机会：查询区、操作弹窗可复用。
- 需要覆盖的状态：加载中 / 空态 / 提交成功 / 提交失败。

## 9. 验收标准
- [x] 系统设置下可见并进入用户管理页面
- [x] 新增/编辑/删除可调用后端接口并反馈结果
- [x] 列表字段与需求一致
- [x] 密码使用哈希存储，不返回明文

## 10. 风险与疑问
- 风险：`auth_user` 原生无 `updated_at` 字段，当前以 `last_login`（兜底 `date_joined`）作为更新时间展示。
- 疑问：若后续需“真实更新时间”，建议补业务扩展字段或独立用户扩展表。

## 11. 确认关卡
- 本次按用户明确“执行一版 + TDD”指令实施。
