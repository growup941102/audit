# 需求文档

## 1. 背景
- 业务背景：数据调度列表支持“删除”操作，需要严格限定删除范围。
- 当前现状：用户反馈当前删除行为有问题，期望不要删除 `c_r_cm_project` 表数据。
- 相关模块：`backend/api/views.py` 中 `operate_data_schedule_tasks` 删除分支。

## 2. 目标
- 核心目标：数据调度删除仅删除 `c_r_cm_task_item_queue` 的相关数据，不触碰 `c_r_cm_project`。

## 3. 范围
### 本次范围
- 修正/加固删除逻辑：面向队列表删除。
- 增加回归测试，锁定行为。

### 不在本次范围
- 不改项目基础表结构。
- 不改数据调度查询展示规则。

## 4. 功能需求
- [ ] 删除操作不对 `c_r_cm_project` 产生任何删改行为。
- [ ] 删除操作删除 `c_r_cm_task_item_queue` 中与目标项目/任务相关记录。
- [ ] 返回 deleted 统计与实际删除行数一致。

## 5. 验收标准
- [ ] 后端删除 SQL 仅作用 `c_r_cm_task_item_queue`。
- [ ] 按项目删除时，队列表相关数据被清理。
- [ ] 回归测试覆盖删除分支。
