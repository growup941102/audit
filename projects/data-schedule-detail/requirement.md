# 需求文档

## 1. 背景
- 业务背景：当前数据调度页只有任务列表，缺少“查看提取结果”的详情界面与可调用接口，无法承载后续结果核验和导出。
- 当前现状：
  - `data-schedule/index` 仅有列表页；
  - “查看提取结果 / 查看详情 / 执行日志”尚未实现真实详情流程；
  - 详情数据目前没有后端接口契约。
- 相关页面/模块：
  - 前端：`frontend/src/pages/(base)/data-fetch/data-schedule/`
  - 后端：`backend/api/views.py`、`backend/api/urls.py`

## 2. 目标
- 核心目标：
  - 新增“数据调度详情（查看提取结果）”页面，界面参考 `demand/detail.png`、`demand/detail2.png`、`demand/detail3.png`；
  - 页面改为调用后端接口；
  - 数据详情支持 `全部 / 提取完整 / 提取缺失` 三类切换。
- 预期价值：
  - 让调度任务结果可追踪、可筛选、可下钻；
  - 支持导出并保留下钻能力，便于离线核查与流转。

## 3. 范围
### 本次范围
- 新增详情页基础布局：任务信息、进度、数据详情区。
- 新增三类结果切换：`全部`、`提取完整`、`提取缺失`。
- 新增后端接口（详情、列表、下钻、下载）。
- 新增“查看”下钻弹窗，支持不同字段点击后展示不同内容（参考 `detail3.png`）。
- 新增“下载 Excel（支持下钻）”能力。

### 不在本次范围
- “预览（眼睛图标）”能力本次不实现（可保留占位/禁用态）。
- 调度执行引擎、本体抽取逻辑不在本次范围。
- 复杂权限细粒度控制（仅沿用现有登录态与基础鉴权）。

## 4. 用户故事
- 作为 `数据审核人员`，我希望在任务详情里切换查看“全部/完整/缺失”字段，并对部分字段继续下钻查看明细，从而快速判断抽取质量。
- 作为 `业务协同人员`，我希望下载后的 Excel 也能按字段下钻查看细项，从而在离线场景仍能追溯结果来源。

## 5. 功能需求
- [ ] 从数据调度列表点击“查看提取结果”进入详情页。
- [ ] 详情页展示任务基础信息（任务标识、项目名、招标编号、创建人、创建时间、执行状态、进度）。
- [ ] 数据详情提供三种筛选：
  - [ ] 全部
  - [ ] 提取完整
  - [ ] 提取缺失
- [ ] 列表行包括：字段名称、字段内容、操作。
- [ ] 当字段支持下钻时，字段内容展示“查看”；点击后打开下钻弹窗。
- [ ] 下钻弹窗支持：新增行、编辑、删除（可先做前端交互 + 后端接口占位）。
- [ ] 下载按钮导出 Excel，并支持下钻（通过多 Sheet + 超链接跳转实现）。

## 6. 非功能需求
- 性能：
  - 详情列表接口支持分页；
  - 下钻数据按需加载，不一次性拉全量。
- 安全性：
  - 接口走现有鉴权；
  - 下载接口仅允许已登录用户。
- 兼容性：
  - 适配当前桌面端主布局；
  - 与现有请求成功码体系兼容。
- 可维护性：
  - 前端拆分 `Page / Services / Types / Modal`；
  - 后端接口参数与响应结构统一。

## 7. 数据与接口影响
- 前端影响：新增 data-schedule 详情页面、API、类型、文案。
- 后端影响：新增 4 组接口：任务概览、字段列表、下钻明细、导出。
- 数据库影响：本次优先按“接口契约 + 可替换数据源”实现，是否落库按后续迭代决定。
- 第三方/MCP 影响：无。

## 8. 交互与界面说明
- 顶部：返回 + 项目标题 + 任务信息卡片 + 进度条。
- 中部：数据详情区 + 三筛选按钮 + 下载按钮。
- 主表：字段行列表，含“编辑/查看”等操作。
- 弹窗：字段详情明细表（不同字段点击查看时列结构可不同）。

## 9. 验收标准
- [ ] 列表页可进入详情页并按任务 ID 拉取数据。
- [ ] 三筛选切换时，接口参数正确传递，数据与计数同步更新。
- [ ] 点击不同“查看”项，下钻弹窗展示对应结构与数据。
- [ ] 下载得到的 Excel 至少包含：概览、字段详情、下钻明细 Sheet；字段详情可跳转到对应下钻 Sheet。
- [ ] 预览按钮保持未实现但不影响主流程。

## 10. 风险与疑问
- 风险：
  - Excel 下钻依赖 xlsx 生成能力，若不引入相关库实现成本高。
  - 下钻数据结构动态化后，前端表格类型需要兜底处理。
- 疑问：
  - 下钻弹窗中的“新增/编辑/删除”是否本期必须落后端持久化，还是先前端交互 + 接口占位。
