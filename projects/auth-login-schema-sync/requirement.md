# 需求文档

## 1. 背景
- 业务背景：当前系统登录、注册、Token 鉴权已在线使用。
- 当前现状：现有库（`tjsj`）具备鉴权相关表，新库尚未具备对应结构。
- 相关页面/模块：登录页、注册、刷新令牌、用户信息、登出等接口。

## 2. 目标
- 核心目标：沉淀当前鉴权表结构，供新库初始化时直接复用。
- 预期价值：避免手工猜字段导致联调失败，保证新库与现有登录鉴权行为一致。

## 3. 范围
### 本次范围
- 记录并输出当前 MySQL 中登录/鉴权相关表结构（DDL）。
- 给出在新库落地的推荐执行方式与顺序。

### 不在本次范围
- 不改业务逻辑代码。
- 不直接在生产库执行写入。

## 4. 用户故事
- 作为后端维护者，我希望快速将现有鉴权表结构应用到新库，从而保证登录和鉴权能力可用。

## 5. 功能需求
- [x] 输出鉴权相关表清单与用途说明。
- [x] 输出可直接用于新库的 SQL 结构文件。
- [x] 提供新库初始化建议（优先迁移命令，SQL 作为兜底）。

## 6. 非功能需求
- 性能：仅结构导出，不涉及大数据量迁移。
- 安全性：不记录明文业务数据，仅记录表结构。
- 兼容性：基于当前 MySQL 8.x 实例实际 DDL。
- 可维护性：文档沉淀到 `projects/backend-knowledge-base/`。

## 7. 数据与接口影响
- 前端影响：无直接影响。
- 后端影响：新库初始化流程更明确。
- 数据库影响：新增文档与 SQL，不改线上数据库。
- 第三方/MCP 影响：无。

## 8. 交互与界面说明
- 可抽离的组件机会：不涉及前端 UI。
- 需要覆盖的状态：不涉及。

## 9. 验收标准
- [x] 能明确列出登录/鉴权所需表。
- [x] 提供一份可执行 SQL 到新库创建表结构。
- [x] 文档可指导团队成员独立完成新库初始化。

## 10. 风险与疑问
- 风险：仅执行 DDL 不会写入 `django_migrations`，后续迁移流程需处理。
- 疑问：新库是否需要同步迁移历史数据（用户、token、权限）。

## 11. 确认关卡
- 本次仅完成文档和 SQL 沉淀，不进入业务代码改造。
