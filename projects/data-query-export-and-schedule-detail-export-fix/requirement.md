# 需求文档

## 1. 背景
- 业务背景：
  数据查询页面已支持按行业和项目名称查询透视结果，但缺少导出能力；同时数据调度详情导出的内容需要进一步收敛，避免导出无业务价值的“操作”列。
- 当前现状：
  - `data-query` 仅支持页面表格查看，不支持导出。
  - `data-schedule` 数据详情导出文件中存在“操作”列（字段详情 sheet 和下钻 sheet）。
- 相关页面/模块：
  - `frontend/src/pages/(base)/data-fetch/data-query/`
  - `frontend/src/service/api/data-query.ts`
  - `backend/api/views.py`

## 2. 目标
- 核心目标：
  1. 为数据查询页面新增导出功能，交互与数据调度导出体验一致。
  2. 调整数据调度数据详情导出内容，去掉“操作”列。
- 预期价值：
  - 提升数据查询结果离线分析效率。
  - 导出结果更聚焦业务数据，减少无效列。

## 3. 范围
### 本次范围
- 新增数据查询导出后端 API（xlsx）及前端触发下载能力。
- 数据调度数据详情导出中移除“操作”列（含下钻 sheet）。

### 不在本次范围
- 不新增数据编辑能力。
- 不改数据查询/数据调度现有筛选规则与主查询逻辑。
- 不改数据库结构。

## 4. 用户故事
- 作为 `数据查询用户`，我希望 `在查询结果页面直接导出当前筛选条件下的数据`，从而 `用于离线查看和汇报`。
- 作为 `数据调度用户`，我希望 `导出文件只包含有效数据字段`，从而 `减少无意义列干扰`。

## 5. 功能需求
- [ ] 需求 1：数据查询页面新增“导出”按钮，按当前筛选条件（industry/projectName）导出 Excel。
- [ ] 需求 2：导出文件应包含与数据查询透视表一致的列定义和数据内容。
- [ ] 需求 2.1：导出主表需具备基础样式（表头、边框、筛选等），提升可读性。
- [ ] 需求 2.2：导出主表中的 `招标代理机构/评标专家信息/开标人员信息` 支持下钻跳转。
- [ ] 需求 3：数据调度数据详情导出中不再包含“操作”列。
- [ ] 需求 4：数据调度下钻 sheet 不再包含“操作”列。

## 6. 非功能需求
- 性能：导出接口在常规数据量下可在可接受时间内返回文件。
- 安全性：沿用现有鉴权，仅登录用户可导出。
- 兼容性：保持现有前端页面布局和交互不回归。
- 可维护性：尽量复用现有导出实现模式和工具函数。

## 7. 数据与接口影响
- 前端影响：
  - `data-query` 页面新增导出交互。
  - `service/api/data-query.ts` 新增导出请求。
- 后端影响：
  - `data-query` 新增导出 API。
  - `data-schedule` 导出构建逻辑调整列输出。
- 数据库影响：无。
- 第三方/MCP 影响：无。

## 8. 交互与界面说明
- 可抽离的组件机会：
  导出下载逻辑可复用已有 blob 下载模式。
- 需要覆盖的状态：加载中 / 空态 / 异常 / 成功
  - 加载中：导出按钮 loading。
  - 空态：可导出空文件（仅表头）或给出统一文件。
  - 异常：toast 提示。
  - 成功：自动下载并提示成功。

## 9. 验收标准
- [ ] 数据查询页面可见并可点击导出按钮。
- [ ] 导出文件字段与页面透视字段一致。
- [ ] 数据查询导出主表样式可读，三列支持“查看”跳转到下钻 sheet。
- [ ] 数据调度数据详情导出文件不含“操作”列。
- [ ] 数据调度下钻 sheet 不含“操作”列。

## 10. 风险与疑问
- 风险：
  - 导出数据量较大时可能影响响应时长。
- 疑问：
  - 数据查询导出范围是否按“当前分页”还是“当前筛选下全部记录”。本次按“当前筛选下全部记录”实现。

## 11. 确认关卡
- 本需求由用户在当前会话直接确认开发，进入编码阶段。
