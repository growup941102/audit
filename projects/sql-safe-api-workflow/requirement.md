# 需求文档

## 1. 背景
- 业务背景：当前开始进入“补接口 + 连 SQL”阶段，数据库安全风险上升，团队需要统一的执行护栏，避免误写和不可逆变更。
- 当前现状：
  - 项目已有 `audit-project-workflow`，但对“SQL 写操作安全门禁”尚未形成可复用的独立 skill。
  - MySQL MCP 当前已配置为 `readonly`，但接口补齐过程中仍可能出现写操作需求。
  - 存在 Java 侧读取 Nacos，而 Python 侧策略尚未明确统一说明。
- 相关模块：
  - `projects/skills-mcp/`
  - `backend/`（接口与配置读取逻辑）

## 2. 目标
- 核心目标：沉淀一个可复用的“安全补接口 + SQL 操作护栏”skill，作为团队默认执行标准。
- 预期价值：
  - 降低误写库、误删库、误改结构风险；
  - 让接口联调过程具备可审计记录；
  - 明确 Python 与 Java 在 Nacos 配置读取上的对齐策略。

## 3. 范围
### 本次范围
- 新增项目级 skill：`safe-sql-api-workflow`。
- 将以下规则写为强制门禁：
  - 默认只读；
  - `INSERT/UPDATE/DELETE/DDL` 必须二次确认；
  - 先测试库验证，再生产执行；
  - 关键写操作必须事务 + 回滚预案；
  - 先 `SELECT` 验证命中范围，再执行写入；
  - 接口联调前后记录“请求参数/影响行数/回滚点”。
- 给出 Python 读取 Nacos 的对齐策略（相对 Java）。

### 不在本次范围
- 不修改业务接口代码。
- 不直接执行数据库写入或结构变更。
- 不调整现有 MCP 安装配置。

## 4. 用户故事
- 作为 `后端/联调协作者`，我希望 `在补接口和连 SQL 时遵循统一安全流程`，从而 `确保数据库变更可控、可回滚、可审计`。

- 兼容性：兼容当前 `audit-project-workflow` 与 MySQL MCP 只读策略。
- 可维护性：规则可在单个 skill 文件集中维护。

## 7. 数据与接口影响

- 数据库影响：无直接写操作。
- 第三方/MCP 影响：仅规范 MySQL MCP 的使用方式，不新增依赖。
