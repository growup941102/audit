- 设计目标：形成“补接口 + 连 SQL”的统一安全执行规范，并可被新线程复用。

## 2. 方案摘要

- 后端方案：无业务代码改动，仅新增流程技能文档。

## 5. 流程设计

### 5.1 默认只读阶段
1. 仅允许结构查看与 `SELECT` 查询；
2. 产出“命中范围预估”（行数 + 样本主键）；
3. 禁止直接写库。

### 5.2 写入预演阶段
1. 先写“变更计划单”（目标表、条件、预估影响行、事务边界、回滚 SQL）；
2. 第一次确认：用户确认计划与影响范围；
3. 在测试库执行并记录结果。

### 5.3 生产执行阶段
1. 第二次确认：执行前再次确认（最终 SQL + 影响行 + 回滚点）；
2. 关键写操作必须显式事务；
3. 执行后记录实际影响行并归档。

### 5.4 联调记录要求
- 联调前记录：请求参数、预估影响行、回滚点。
- 联调后记录：响应结果、实际影响行、是否触发回滚。

## 6. Nacos 对齐设计（Java -> Python）
- Java（Spring Cloud Alibaba）通常由框架自动装配读取 Nacos 配置。
- Python 采用显式 SDK 调用（`nacos-sdk-python`）：
  - 启动时拉取配置；
  - 注册监听器处理动态更新；
  - 失败时回退本地配置（`.env`/本地文件）；
  - `dataId/group/namespace` 与 Java 使用同一命名与来源。

## 9. 风险
- 技术风险：DDL 在 MySQL 场景下部分语句无法依赖事务回滚，需要预备反向 DDL 或备份恢复路径。
- 回滚/兜底方案：所有写入动作前必须提前声明回滚点；不满足条件则不执行写入。
