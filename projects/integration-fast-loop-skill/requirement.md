# 需求文档

## 1. 背景
- 业务背景：当前进入前后端联调问题修复阶段，问题数量和沟通频次上升。
- 当前现状：排查进展、阻塞点、待决策项分散在聊天中，容易出现重复确认和信息遗漏。
- 相关页面/模块：联调涉及的前端页面、后端 API、日志与配置排查流程（不限具体业务模块）。

## 2. 目标
- 核心目标：固化一套“联调快循环沟通”skill，降低沟通成本并提升问题闭环速度。
- 预期价值：统一状态表达、减少上下文切换、明确何时需要用户决策。

## 3. 范围
### 本次范围
- 在 `projects/skills-mcp/` 下新增联调沟通 skill。
- 约定联调阶段的问题卡模板、节奏规则、决策门禁、验证闭环规则。
- 补充项目内文档，使新线程可快速发现并使用该 skill。

### 不在本次范围
- 不修改任何前端/后端业务代码。
- 不变更现有接口契约、数据库结构、部署流程。

## 4. 用户故事
- 作为 `需求提出者/协作者`，我希望 `联调修复阶段的沟通有统一节奏与模板`，从而 `更快判断进度、风险和下一步决策`。

## 5. 功能需求
- [ ] 新增一个项目专用 skill，名称明确、触发条件清晰。
- [ ] skill 提供标准问题卡（现象、复现、定位、下一步、是否需决策）。
- [ ] skill 规定固定进展同步频率与状态标签（如已闭环/待复测/阻塞）。
- [ ] skill 明确哪些动作必须停下来等待用户确认。
- [ ] 在项目 skill 指南中补充该 skill 的使用入口。

## 6. 非功能需求
- 性能：不涉及运行时性能。
- 安全性：不引入写库、远程执行等高风险动作。
- 兼容性：兼容现有 `audit-project-workflow` 规则，不冲突。
- 可维护性：内容简洁、可复用、可在后续联调中直接套用。

## 7. 数据与接口影响
- 前端影响：无业务代码影响。
- 后端影响：无业务代码影响。
- 数据库影响：无。
- 第三方/MCP 影响：无强制依赖。

## 8. 交互与界面说明
- 可抽离的组件机会：不涉及前端 UI。
- 需要覆盖的状态：问题进行中 / 已闭环 / 待复测 / 阻塞。

## 9. 验收标准
- [ ] 新线程显式使用该 skill 时，能按统一模板输出联调进展。
- [ ] 能清晰区分“可继续执行”和“需用户确认”的场景。
- [ ] 能在交付总结中快速给出闭环状态与残留风险。

## 10. 风险与疑问
- 风险：规则过重会降低执行速度，需保持轻量。
- 疑问：后续是否要把该 skill 进一步细分为“单问题排查”和“多问题并行联调”两个模式。

## 11. 确认关卡
- 未经用户确认，不进入编码阶段。
