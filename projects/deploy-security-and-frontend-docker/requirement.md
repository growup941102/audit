# 需求文档

## 1. 背景
- 当前部署配置中存在默认明文凭据，且前端容器仍是开发模式运行。
- 需要在服务器部署时同时满足“敏感信息最小暴露”和“前端可容器化生产部署”。

## 2. 目标
- 清理仓库中可见的默认敏感凭据，改为占位符或环境变量注入。
- 前端支持通过 Docker 生产部署（静态资源 + 反向代理后端 API）。
- 保持一条命令可拉起完整环境（前端、后端、MySQL）。

## 3. 范围
### 本次范围
- `.env`、`docker-compose.yml` 的默认敏感配置治理。
- `frontend/Dockerfile` 改为生产镜像构建。
- 新增前端 Nginx 配置与生产环境变量文件。
- 补充部署说明文档。

### 不在本次范围
- 业务接口逻辑改造。
- 生产级运维体系（TLS、WAF、日志平台、监控告警）。

## 4. 验收标准
- [ ] 仓库默认配置中不再出现真实密码/密钥。
- [ ] `docker compose up -d --build` 可启动前端、后端、MySQL 三个服务。
- [ ] 前端可通过容器访问并正常请求 `/api/*`。
- [ ] 文档明确说明必须由环境变量注入真实凭据。
