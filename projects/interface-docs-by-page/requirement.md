# 需求文档

## 1. 背景
- 业务背景：联调和二次开发阶段，需要能快速定位“某个页面对应哪些接口、在哪写、读哪些表、返回什么结构”。
- 当前现状：已有全局契约文档，但缺少“按页面维度”可快速检索的接口文档。
- 相关页面/模块：优先覆盖 `数据概览` 页面，后续逐页扩展。

## 2. 目标
- 核心目标：建立“按界面查接口文档”的统一入口。
- 预期价值：
  - 降低前后端联调沟通成本；
  - 让新同学可快速理解页面到接口的调用链；
  - 让后续新增接口时有统一的文档模板可复用。

## 3. 范围
### 本次范围
- 新增页面接口文档总索引。
- 以 `数据概览页` 为样例，补齐完整接口说明（summary/detail/ranking）。
- 补充“后端接口编写示例模板”。
- 更新知识库 README 入口。

### 不在本次范围
- 不修改业务代码和接口逻辑。
- 不一次性覆盖所有页面，仅先落地文档体系与样例页。

## 4. 用户故事
- 作为 `前后端协作者`，我希望 `能按页面查到对应接口文档`，从而 `快速完成联调和问题定位`。

## 5. 功能需求
- [ ] 需求 1：提供统一入口文档，按页面列出文档链接。
- [ ] 需求 2：提供数据概览页的接口清单、调用链、表依赖和状态口径。
- [ ] 需求 3：提供可复用的后端接口编写示例。
- [ ] 需求 4：明确后续扩展规范（新增页面文档时应包含哪些字段）。

## 6. 非功能需求
- 性能：不涉及运行时性能。
- 安全性：仅文档变更，无写库与远程操作。
- 兼容性：与当前 `projects/backend-knowledge-base` 目录结构一致。
- 可维护性：统一结构、可持续扩展到更多页面。

## 7. 数据与接口影响
- 前端影响：无代码变更。
- 后端影响：无代码变更。
- 数据库影响：无。
- 第三方/MCP 影响：无。

## 8. 交互与界面说明
- 可抽离的组件机会：不涉及。
- 需要覆盖的状态：文档需明确接口成功/失败与常见报错说明。

## 9. 验收标准
- [ ] 能从一个入口找到“数据概览页”的接口文档。
- [ ] 文档能回答：接口路径、参数、返回、后端入口、SQL表依赖、状态逻辑。
- [ ] 文档包含一个可照抄的后端接口编写示例。

## 10. 风险与疑问
- 风险：文档如果不持续维护，可能与代码脱节。
- 疑问：后续是否需要在 CI 中增加文档一致性检查（例如路由变更提醒）。

## 11. 确认关卡
- 本次为文档沉淀需求，不涉及业务代码编写。
