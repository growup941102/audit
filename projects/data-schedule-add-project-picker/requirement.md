# 需求文档

## 1. 背景
- 业务背景：数据调度「新增」流程需要重新设计，当前弹窗是目录树多选，不符合最新交互。
- 当前现状：
  - 前端弹窗为「目录 + 树」结构，支持多选。
  - 后端 `GET /api/data-schedule/select-data/` 返回目录树数据。
- 相关页面/模块：
  - 页面：`/data-fetch/data-schedule?mode=add`
  - 前端模块：`ScheduleCreateView`、`ScheduleChooseDataModal`
  - 后端接口：`GET /api/data-schedule/select-data/`

## 2. 目标
- 核心目标：将“新增”弹窗重做为「搜索框 + 项目单选列表」。
- 预期价值：
  - 降低选择复杂度，避免树结构误选。
  - 与“项目级新增”业务语义一致（单任务选择单项目）。

## 3. 范围
### 本次范围
- 重做新增弹窗交互：
  - 顶部搜索框（按项目名过滤）。
  - 下方项目单选（radio）。
- 后端 `select-data` 返回可选项目列表（非目录树）。
- 可选项目范围严格限定为：
  - `industry` 非空；且满足以下其一：
    - 不存在 `c_r_cm_file_prepare.project_id = c_r_cm_project.project_id`；
    - 存在 `c_r_cm_file_prepare`，但不存在项目级队列：`c_r_cm_task_item_queue.file_id LIKE 'PROJECT:%'`。
- 按 TDD 执行：先补失败测试，再实现，再回归。
- 点击“创建”时调用重试接口：
  - 目标接口：`POST /admin/retry`（通过前端代理转发至 `10.1.221.233:9528`）
  - 关键入参：`projectIds`（来自弹窗确认后的项目选择）
  - 固定参数：`stepNo=1`、`subStep=''`、`fileIds=[]`、`priority=838`、`preempt=true`、`force=true`、`onlyStep=false`、`mode='pipeline'`、`payload={}`

### 不在本次范围
- 数据调度列表页与详情页逻辑。

## 4. 用户故事
- 作为 `数据调度操作员`，我希望在新增弹窗中通过搜索快速定位项目并单选，从而更准确发起新增任务。

## 5. 功能需求
- [ ] 点击“新增/选择数据”后弹窗打开，展示搜索框与项目单选列表。
- [ ] 搜索关键字变化时，列表按 `projectName` 实时过滤（前端过滤）。
- [ ] 弹窗仅允许选中一个项目。
- [ ] 项目列表数据来自后端接口，并符合上述可选规则。
- [ ] 当无数据或过滤无结果时，展示明确空态。
- [ ] 点击“创建”会调用重试接口并传入 `projectIds`。
- [ ] 前端代理可将请求转发到 `10.1.221.233:9528`。

## 6. 非功能需求
- 性能：首屏接口一次返回项目列表，前端本地过滤。
- 安全性：本需求仅涉及只读查询，遵循 `safe-sql-api-workflow` 默认只读规则。
- 兼容性：保留现有接口地址，避免路由层变更。
- 可维护性：前端选择逻辑集中在 `ScheduleCreateView`，弹窗组件仅做展示与交互。

## 7. 数据与接口影响
- 前端影响：
  - `ScheduleCreateView` 状态模型由“目录树多选”改为“项目单选”。
  - `ScheduleChooseDataModal` 改为搜索+radio结构。
  - `DataSchedule` 创建事件从占位提示改为真实 API 调用。
- 后端影响：
  - `get_data_schedule_select_data` 的 `data` 结构从树改为项目列表。
- 数据库影响：
  - 仅只读查询 `c_r_cm_project`、`c_r_cm_file_prepare`、`c_r_cm_task_item_queue`。
- 第三方/MCP 影响：
  - 无 MCP；新增前端代理配置（开发模式）。

## 8. 交互与界面说明
- 可抽离的组件机会：弹窗保持独立组件，页面负责状态管理与数据过滤。
- 需要覆盖的状态：加载中 / 空态 / 异常 / 成功。

## 9. 验收标准
- [ ] 弹窗界面为「搜索框 + 项目单选列表」，不再展示目录树。
- [ ] 可选项目满足给定 SQL 规则。
- [ ] 选中项目后页面摘要仅显示单项目结果。
- [ ] 后端相关测试与前端类型检查通过。
- [ ] 点击“创建”可成功命中 `/admin/retry` 代理路径并携带 `projectIds`。

## 10. 风险与疑问
- 风险：若项目量极大，一次性返回列表可能造成前端过滤成本上升。
- 疑问：远端 `admin/retry` 返回结构在不同环境是否一致（当前前端按宽松 JSON/文本兼容处理）。

## 11. 确认关卡
- 当前需求由用户已明确授权进入开发；本次仅执行只读查库逻辑，不做写库操作。
