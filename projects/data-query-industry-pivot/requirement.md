# 需求文档

## 1. 背景
- 业务背景：当前 `数据查询` 页面仅为占位内容，尚未支持按行业维度进行项目字段查询与展示。
- 当前现状：
  - 前端路由 `/data-fetch/data-query` 存在，但页面仅显示“数据查询”文本；
  - 后端暂无“行业 + 项目名称”搜索并返回字段透视表的专用接口；
  - 用户无法在同一行业下横向对比各项目的字段内容。
- 相关页面/模块：
  - 前端：`frontend/src/pages/(base)/data-fetch/data-query/index.tsx`
  - 后端：`backend/api/views.py`、`backend/api/urls.py`
  - 业务表：`c_r_cm_project`（行业字段 `industry`）及数据调度详情关联表。

## 2. 目标
- 核心目标：
  - 实现“数据查询”页面，支持按“项目行业 + 项目名称”搜索；
  - 项目行业默认勾选第一个可用项；
  - 结果表按“列式透视”展示：表头为“数据调度详情-数据详情”字段名称，表格行为项目，单元格为字段内容。
- 预期价值：
  - 快速查看同一行业下不同项目的字段差异；
  - 复用已有数据调度详情字段定义，降低口径不一致风险。

## 3. 范围
### 本次范围
- 新增数据查询页面搜索区：
  - 项目行业（必选，默认第一个）
  - 项目名称（可选，模糊搜索）
- 新增后端只读接口：
  - 获取行业选项
  - 获取行业项目字段透视数据
- 列式透视结果展示：
  - 固定列：项目名称
  - 动态列：字段名称（来源于数据调度详情字段名）
- 全流程按 TDD 执行（先测后改）。

### 不在本次范围
- 不做任何写库操作（仅 `SELECT`）。
- 不实现字段编辑、下钻弹窗、导出等增强功能。
- 不引入新的外部依赖或新 MCP。

## 4. 用户故事
- 作为 `数据查询使用者`，我希望 `按项目行业和项目名称筛选，并看到同一行业项目的字段透视表`，从而 `快速比对项目数据内容`。

## 5. 功能需求
- [ ] 需求 1：页面打开后自动拉取行业选项，并默认选择第一个行业。
- [ ] 需求 2：支持输入项目名称关键字进行模糊搜索。
- [ ] 需求 3：点击查询后展示透视表：
  - [ ] 表头字段名来自数据调度详情“数据详情”的字段名；
  - [ ] 每行代表一个项目；
  - [ ] 单元格内容为对应字段的字段内容（缺失显示 `--`）。
- [ ] 需求 4：行业切换后自动重查并刷新表格。
- [ ] 需求 5：空结果时显示空态，接口异常时显示错误提示。

## 6. 非功能需求
- 性能：
  - 透视查询接口支持分页（默认每页 10，最大 50）。
- 安全性：
  - 仅允许只读查询；
  - 参数化 SQL，禁止拼接不安全输入。
- 兼容性：
  - 保持现有前端请求成功码与错误处理机制一致。
- 可维护性：
  - 前端拆分页面/搜索组件/service/hooks/types；
  - 后端将行业查询与透视构造封装为独立 helper。

## 7. 数据与接口影响
- 前端影响：
  - 新增 data-query 页面真实查询逻辑与动态表格渲染。
- 后端影响：
  - 新增数据查询只读接口（行业列表 + 透视列表）。
- 数据库影响：
  - 仅只读查询 `c_r_cm_project` 及详情相关表；
  - 不执行 `INSERT/UPDATE/DELETE/DDL`。
- 第三方/MCP 影响：
  - 无（本期优先本地代码 + 只读 SQL 方案）。

## 8. 交互与界面说明
- 搜索区：项目行业（Select）+ 项目名称（Input）+ 查询/重置按钮。
- 表格区：
  - 左侧固定列：项目名称；
  - 右侧动态字段列：字段名；
  - 支持横向滚动。
- 状态：加载中 / 空态 / 异常 / 成功。

## 9. 验收标准
- [ ] 进入页面后，项目行业默认选中第一个选项并自动查询。
- [ ] 输入项目名称后查询结果按条件过滤。
- [ ] 表头字段名与数据调度详情字段名口径一致。
- [ ] 表格内容按行业下项目数据正确展示，缺失值显示 `--`。
- [ ] 全流程仅只读查询，无写库行为。

## 10. 风险与疑问
- 风险：
  - 字段集合为动态并集时，列数可能较多，影响可读性与性能；
  - 若项目与详情映射关系缺失，部分项目可能无法产出字段值。
- 疑问：
  - 行业选项默认“第一个”的排序规则采用字典序（`industry ASC`）是否可接受。
